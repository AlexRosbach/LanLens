# Windows agent: private or self-signed HTTPS certificates

TLS verification is enabled by default. On the Deep Scan → Windows Agent installation page, enable **Explicitly trust an untrusted certificate** if necessary. No certificate fingerprint is required.

The generated installation command allows untrusted certificate chains for downloading the installer, compiling and enrolling the agent, and subsequent inventory reports. The setting is persisted as a boolean in the protected agent.json configuration. HTTPS and a presented server certificate are required; redirects are disabled. With the explicit exception, chain, hostname and validity-date verification are bypassed. Bootstrap and installer use request-local certificate callbacks instead of PowerShell web cmdlets. The Windows trust store is not changed. Existing explicit fingerprint configurations retain their pin checks.

**Security warning:** an untrusted certificate chain cannot authenticate the server. An attacker could impersonate the server, deliver modified executable code, or intercept enrollment and reporting credentials. Prefer a normally trusted private or public CA certificate. Only enable the exception where the network and endpoint are trusted.

Linux agent behavior is unchanged.

## Local diagnostics and updating existing Windows agents

Run the ordinary installation command again to update an existing Windows agent. No update switch or new enrollment token is required, even if the original token has already been used or expired. Deep Scan → Windows Agent also lets you copy that command without creating another token. Run elevated using the original server URL and certificate option. The existing agent registration, report sequence and configuration are retained. The service writes `C:\ProgramData\LanLensAgent\agent.log` (UTC); daily archives are named `agent-YYYY-MM-DD.log`. Older archives are removed after 30 calendar days when logging. Logs include collector status, report endpoint, counts, sequence, HTTP status and accepted device/run IDs, but never enrollment tokens, bearer credentials or inventory payloads. New enrollments persist the selected MAC to prevent switching adapters on reboot. Existing configurations without a saved MAC continue using the previous selection behavior; a 409 identity mismatch requires checking the enrolled device MAC. In Device → Deep Scan, agent status reports the last accepted sequence and run, and findings are grouped by source even without SSH/WinRM configuration. First and changed reports appear in Change Timeline; identical reports update the last-report status without adding timeline noise.

### Upgrade, uninstall and source timeline

Running the installation command for the same server upgrades the local binary instead of requesting another registration whenever usable local enrollment credentials exist. A missing service or executable is repaired without replacing `agent.json`; the saved enrollment, MAC, reporting interval, TLS settings and sequence are preserved. The downloaded command always fetches the current installer, so a previously copied command can be reused after upgrading LanLens. If an update cannot start, the installer restores the previous executable when available. A missing or damaged local enrollment cannot be recovered from a single-use token: restore the original `agent.json`, or uninstall and revoke the previous token in LanLens before a new enrollment. Windows Settings → Apps → Installed apps → LanLens Inventory Agent supports uninstall after upgrade or new installation. Uninstall stops/removes the service, attempts authenticated revocation, removes owned local files/logs and the Windows app registration, and retains server inventory. A failed local cleanup retains the uninstall entry and script so it can be retried. App registration uses the native registry view and removes legacy 32-bit entries. If revocation fails, revoke the old token manually. The device Deep Scan badges distinguish configured/enrolled sources without data from sources with stored observations; green means data exists, not that a source is currently online. Inventory changes are compared within each source, with individual findings and bounded before/after summaries. Missing collectors do not delete observations.
