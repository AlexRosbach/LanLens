# Windows agent: private or self-signed HTTPS certificates

TLS verification is enabled by default. On the Deep Scan → Windows Agent installation page, enable **Explicitly trust an untrusted certificate** if necessary. No certificate fingerprint is required.

The generated installation command allows untrusted certificate chains for downloading the installer, compiling and enrolling the agent, and subsequent inventory reports. The setting is persisted as a boolean in the protected agent.json configuration. HTTPS and a presented server certificate are required; redirects are disabled. With the explicit exception, chain, hostname and validity-date verification are bypassed. Bootstrap and installer use request-local certificate callbacks instead of PowerShell web cmdlets. The Windows trust store is not changed. Existing explicit fingerprint configurations retain their pin checks.

**Security warning:** an untrusted certificate chain cannot authenticate the server. An attacker could impersonate the server, deliver modified executable code, or intercept enrollment and reporting credentials. Prefer a normally trusted private or public CA certificate. Only enable the exception where the network and endpoint are trusted.

Linux agent behavior is unchanged.

## Local diagnostics and updating existing Windows agents

Run the ordinary installation command again to update an existing Windows agent. No update switch or new enrollment token is required for an active registration, even if the original token has already been used or expired. Revoking a used installation token disables that agent; expiration alone does not. Deep Scan → Windows Agent also lets you copy that command without creating another token. Run elevated using the original server URL and certificate option. The existing agent registration, report sequence and configuration are retained. The service writes `C:\ProgramData\LanLensAgent\agent.log` (UTC); daily archives are named `agent-YYYY-MM-DD.log`. Older archives are removed after 30 calendar days when logging. Logs include collector status, report endpoint, counts, sequence, HTTP status and accepted device/run IDs, but never enrollment tokens, bearer credentials or inventory payloads. New enrollments persist the selected MAC to prevent switching adapters on reboot. Existing configurations without a saved MAC continue using the previous selection behavior; a 409 identity mismatch requires checking the enrolled device MAC. In Device → Deep Scan, agent status reports the last accepted sequence and run, and findings are grouped by source even without SSH/WinRM configuration. First and changed reports appear in Change Timeline; identical reports update the last-report status without adding timeline noise.

### Upgrade, uninstall and source timeline

For an active saved identity, running the installation command for the same server upgrades the local binary without requesting another registration. A missing service or executable is repaired without replacing `agent.json`; the saved enrollment, MAC, reporting interval, TLS settings and sequence are preserved. The downloaded command always fetches the current installer, so a previously copied command can be reused after upgrading LanLens. If an update cannot start, the installer restores the previous executable when available. A missing or damaged local enrollment cannot be recovered from a single-use token: restore the original `agent.json`, or uninstall and revoke the previous token in LanLens before a new enrollment. Windows Settings → Apps → Installed apps → LanLens Inventory Agent supports uninstall after upgrade or new installation. Uninstall stops/removes the service, attempts authenticated revocation, removes owned local files/logs and the Windows app registration, and retains server inventory. A failed local cleanup retains the uninstall entry and script so it can be retried. App registration uses the native registry view and removes legacy 32-bit entries. If revocation fails, revoke the old token manually. The device Deep Scan badges distinguish configured/enrolled sources without data from sources with stored observations; green means data exists, not that a source is currently online. Inventory changes are compared within each source, with individual findings and bounded before/after summaries. Missing collectors do not delete observations.


### Recovering a revoked registration

Create a **new installation command** in Deep Scan → Windows Agent and run it on the existing installation. The installer checks the saved identity through the authenticated `/api/agents/identity` endpoint. An active identity keeps its credentials and ignores the command's enrollment token. Only a definitive HTTP 401 allows registration with the supplied fresh token; used, expired or revoked tokens are still rejected by the server. A timeout, temporary server failure or an older server without this endpoint never causes automatic registration or deletion of local credentials. The installer may still update local program files if the asset downloads succeed, and warns when identity verification was unavailable.

Recovery uses the saved MAC and requires that adapter to be available. A legacy configuration without a MAC must have its enrolled `primary_mac` restored first; the installer never guesses which adapter was registered. A platform or saved-MAC mismatch is an error. Recovery stops the service and waits for its process to exit before reading its latest saved settings and replaces the configuration atomically after successful enrollment. The new identity starts at sequence zero; reporting interval, TLS settings and other saved options remain. If the new executable cannot start, the previous executable is restored with the newly issued credentials, never with the revoked identity. Missing or corrupt local credentials still require restoration or an explicit fresh installation.

The agent executable embeds the LanLens logo. Windows app registration also references the installed icon so LanLens Inventory Agent can be recognized in Windows Settings. Users receive read access only to the icon, plus non-inherited traverse permission on the install directory; credentials and executable permissions remain private.
