# VMware vSphere discovery (#142)

Enable Advanced View, open Settings → Inventory tools → VMware vSphere / vCenter, enable the integration and save a vCenter HTTPS origin plus a read-only service account. Test connection, then Discover devices. The account needs read access (System.Read and visibility to the relevant hosts and VMs); no guest credentials or VM control privileges are required. Use the system trust store or mount a combined CA bundle read-only and set SSL_CERT_FILE. Certificate and hostname verification and DNS pinning are mandatory. Passwords use the existing Fernet credential encryption and are not returned by the API. Changing the origin or username clears the stored password.

This first implementation targets vCenter 7+ REST (/api/session, /api/vcenter/host, /api/vcenter/vm, per-VM details and guest network interfaces). No PowerCLI or extra runtime package is required. Standalone ESXi, scheduling, multiple vCenter instances and environments exceeding 100 hosts / 500 VMs are follow-up scope. Discovery is manual and bounded; a failed inventory request does not overwrite the last snapshot. Guest IP availability depends on VMware Tools and permissions. Powered-off VMs may still have hardware MAC addresses. A power state does not establish network reachability.

Existing devices are matched by real MAC, never solely by guest IP; unmatched VMs with non-conflicting real MACs are created as unregistered devices. Duplicate MACs, conflicting IPs, changed NICs and ambiguous matches are not guessed. Hosts are listed even if not yet present in LanLens; exact existing hostname/IP matches allow host/VM relationships. No synthetic MACs are generated, and no upstream VM changes or device deletions are performed. Previously observed objects not seen during a later discovery are marked stale. Device data and manual relationships are preserved. Select a linked inventory name to open the device detail.

API reference: https://developer.broadcom.com/xapis/vsphere-automation-api/latest/

A manual discovery uses a 90-second collection timeout (plus session cleanup), below the default reverse-proxy API timeout. Large or slow inventories can require a later batched/background discovery implementation.
